## Проекты и запуск

- Этот репозиторий: Python, aiogram, FastAPI, SQLAlchemy, PostgreSQL/SQLite, Redis, Alembic; версии определяют `pyproject.toml` и `uv.lock`.
- Фронтенд: `/Users/c0mrade/WebstormProjects/bedolaga-cabinet`. Перед его изменением читать его `AGENTS.md`.
- Python сейчас требуется `3.14.*`; Ruff `target-version` отдельно настроен в `pyproject.toml` — не менять версии попутно.
- Зависимости: `uv sync --frozen --group dev`. Команды выполнять через `uv run --frozen`, чтобы случайно не переписать lockfile. Не откатывать `uv.lock` или другие файлы без проверки diff.
- Запуск приложения: `uv run --frozen python main.py`; требует настроенного окружения и может обращаться к Telegram, платёжным провайдерам и панели. Для изучения не запускать с боевыми реквизитами.

## Архитектурные правила

- `main.py` управляет ботом, HTTP-сервером, фоновыми задачами и завершением. Единая HTTP-точка — `app/webserver/unified_app.py`.
- `app/cabinet` — API личного кабинета; `app/webapi` — отдельный программный API; `app/handlers` — Telegram. Бизнес-правила переиспользовать через `app/services`.
- Записи аккаунтов Remnawave проводить через `app/services/panel_sync`. Прямые `api.create_user`/`api.update_user` вне пакета запрещены; проверка — `tests/services/panel_sync/test_no_bypass.py`.
- Не смешивать оплаченный срок/лимит с временным grace-overlay; правила описаны в `docs/grace-access.md` и соответствующих сервисах.
- Изменения покупки, продления, списаний проверять для Telegram и кабинета, trial/paid, daily/period, single/multi-subscription, повторного webhook и конкурентных запросов по затронутому сценарию.
- RBAC и принадлежность объектов проверяются на сервере. Изменения API сверять со схемами и вызовами фронтенда.
- Полная интеграция внешнего API означает сверку всех нужных ручек и параметров с контрактом сервиса, включая фактические вызовы из кабинета.
- Настройки могут переопределяться из БД: учитывать `settings_store`, `system_settings_service`, `system_settings`, а не только `.env`.

## Проверки

- По требованию владельца от 2026-11-04 новый код хранения данных и его интеграционные проверки ориентировать на PostgreSQL. Не добавлять поддержку SQLite, обходы его ограничений или замену PostgreSQL SQLite-тестами.

- Код: `uv run --frozen ruff check app tests`; формат: `uv run --frozen ruff format --check app tests`.
- Тесты: `uv run --frozen pytest -q`; выбирать сначала затронутые тесты. Моки из `tests/conftest.py` не заменяют проверку реального PostgreSQL.
- PostgreSQL: отдельная тестовая БД через `TEST_DATABASE_URL`, `REQUIRE_POSTGRES_TESTS=1`; команды и контейнер описаны в `Makefile`. CI проверяет PostgreSQL 18 и 15. Не использовать production-БД.
- При изменении структуры кода пересобирать `docs/project_structure_reference.md` командой `make docs-structure`; вручную файл не редактировать.
- UI проверять во фронтенде, включая WebKit, 390/1280 и обе темы при визуальных изменениях. Отдельно сообщать, что не запускалось и почему.
- Перед завершением проверить `git diff --check`, diff и отсутствие секретов. Не заявлять, что тесты прошли, без свежего результата.
